# Yinji 产品与安全边界

## 已确定的规则

### 1. 视觉盖章与数字签名严格分离

浏览器端只执行视觉盖章、手写图像叠加、扫描效果和证据记录，不接收私钥、证书口令或远程签名凭据，也不宣称签署者身份可信。

需要数字签名时必须走 `yinji-cli sign` 的外部程序契约。外部程序生成文件后，仍须由独立 PDF 签名验证器检查证书链、签名覆盖范围、吊销状态和时间戳。Yinji 只确认外部程序返回了非空文件。

### 2. 印章默认只保存一个浏览器会话

新保存的印章进入 `sessionStorage`，关闭整个浏览器会话后消失。长期保存只能使用用户口令加密的 `.yinji-vault.json`。

旧版 `localStorage` 印章库不会被静默删除：首次运行会复制到当前会话并显示警告。用户完成加密备份后，通过“清除旧数据”明确删除。这样不以安全升级为名静默销毁用户素材。

### 3. 人工导出为单个证据包

人工界面每次导出只下载一个 `.yinji.zip`，其中包含结果 PDF/PNG 和 `yinji-evidence/v1` JSON。避免浏览器多文件下载权限导致侧车丢失。

Agent CLI 不走浏览器下载，直接把结果文件和 JSON 分别写入 `--output-dir`，便于后续程序读取。两条路径的 manifest 和哈希规则完全相同。

## 不在 Yinji 内部实现

- 证书申请、私钥托管、HSM/KMS、吊销查询与证书信任策略；
- 服务端文件上传、多人审批和法律身份认证；
- 自动删除旧版持久印章库；
- 绕过浏览器、操作系统或证书提供方的安全确认。
