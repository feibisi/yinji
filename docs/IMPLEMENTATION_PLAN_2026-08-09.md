# Yinji 素材处理、证据链与自动化实施计划

日期：2026-08-09  
执行者：[CX]

## 1. 目标

1. 修复印章亮度、去白底、旋转和印章库的已确认缺陷。
2. 让普通导出、扫描导出和批量导出使用同一套 SHA-256 与证据清单格式。
3. 用版本化模板描述批量盖章规则，并在骑缝章导出前检查每页覆盖情况。
4. 默认不持久保存印章；需要持久化时提供本机加密保险库能力。
5. 给自动化调用提供稳定的 `stamp`/`sign` 接口；私钥和证书不进入浏览器存储。
6. 补齐像素、状态、导出、CLI 和真实浏览器回归测试。

## 2. 产品边界

- Yinji 继续是本地优先的视觉盖章工具。
- SHA-256、侧车清单和本机日志是证据材料，不等同于可靠电子签名。
- PKI 签名由外部签名程序完成；浏览器只生成待签文件和清单。
- 纯前端版本不声称提供组织级权限控制或不可篡改集中审计。

## 3. 任务与验收

### A. 素材处理

- 保留原始素材和处理后素材，避免连续操作累积失真。
- 去背景改为边缘连通判定，保留封闭区域中的白色内容。
- 去背景操作可等待、可反馈，完成前禁止重复触发。
- 旋转输出按旋转后包围盒扩展，长条签名不裁切。
- 印章库正确保存 `0` 等合法数值，损坏素材不覆盖当前有效状态。
- 验收：像素 Alpha、亮度差、旋转尺寸、存储往返测试全部通过。

### B. 证据包

- 清单 schema：`yinji-evidence/v1`。
- 至少记录源文件/成品 SHA-256、页数、操作、时间、应用版本。
- 普通、扫描、批量三条导出路径复用同一个实现。
- 验收：固定输入重复计算哈希一致，清单字段和文件名一致。

### C. 批量模板与骑缝章校验

- 模板 schema：`yinji-stamp-template/v1`。
- 支持页范围、锚点、偏移、尺寸、透明度。
- 批量处理不再硬编码每页居中。
- 骑缝章组记录覆盖页，导出前可检测缺页。
- 验收：模板清洗、坐标计算、缺页/完整覆盖测试通过。

### D. 印章安全

- 未主动保存的素材只存在于当前页面会话。
- 持久保存提供 AES-GCM 加密数据格式和口令派生密钥。
- 不保存口令，不提供虚假恢复能力。
- 验收：加密往返、错误口令失败、明文不出现在密文载荷。

### E. CLI 与签名接口

- `stamp` 读取模板并驱动现有浏览器处理链。
- `sign` 调用配置的外部命令，使用明确的输入/输出文件契约。
- `sign` 默认关闭；未配置时失败并给出可操作错误。
- 验收：帮助、参数错误、stamp dry-run、sign 未配置和 mock signer 测试通过。

## 4. 顺序

1. 素材处理与测试基础。
2. 统一导出产物与证据清单。
3. 模板和骑缝章校验。
4. 加密保险库。
5. CLI/签名 hook。
6. 用户说明、技术设计、变更记录和交接。
7. 全量测试与桌面/移动端验收。

## 5. 停止条件

- 需要集中身份、组织权限、证书托管或生产 TSA 凭据时停止在接口层，不生成假实现。
- 任何测试出现回归，先修复后再进入下一阶段。
- 真实证书、口令、令牌不写入仓库、日志或对话。
